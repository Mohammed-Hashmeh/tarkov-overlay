# Tarkov Interactive Map Overlay — Implementation Plan

## Context

The user wants a local desktop version of interactive Escape from Tarkov map sites (reference: https://tarkov-map-pro.exfil.workers.dev/, tarkov.dev/maps). Instead of a browser tab, it should run as a local app that can sit **on top of the game** — either as a transparent always-on-top overlay (game in borderless windowed mode) or as a normal window on a second monitor, switchable between the two.

Decisions made with the user:
- **Display**: both overlay mode and normal-window mode, switchable.
- **Position tracking**: core feature — plot the player on the map from in-game screenshots (the community-accepted, anti-cheat-safe technique), plus auto-detect the loaded map from game logs.
- **Features**: extracts (PMC/Scav), quest markers (with a *local* quest checklist — no account sync), spawns & bosses, loot & keys.
- **Data**: bundled snapshot from the tarkov.dev API/assets, refreshed by re-running a fetch script after game patches. No network calls at runtime.
- **Stack**: Electron (best support for transparent click-through overlays, global hotkeys, file watching).

## Verified technical facts (from research)

These were confirmed by reading tarkov.dev data and TarkovMonitor source (`https://raw.githubusercontent.com/the-hideout/TarkovMonitor/master/TarkovMonitor/GameWatcher.cs`):

1. **Screenshot position trick**: EFT writes screenshots to `%USERPROFILE%\Documents\Escape From Tarkov\Screenshots`. Filename format parsed by TarkovMonitor:
   - File regex: `\d{4}-\d{2}-\d{2}\[\d{2}-\d{2}\]_?(?<position>.+) \(\d\)\.png`
   - Position part: `x, y, z` (2 decimals each) followed by a rotation **quaternion** `rx, ry, rz, rw`. Note EFT/Unity axes: `x`/`z` are horizontal ground plane, `y` is height (used for floor-layer selection); yaw for the facing cone comes from the quaternion.
2. **Map auto-detection**: tail the newest `application_*.log` under the EFT install's `Logs` folder (install path found via registry, same approach as TarkovMonitor's `GetRegistryInstallLocations`; also allow manual path config). Key line: `application|scene preset path:maps/<name>.bundle` → match against each map's `scenePath`. `application|LocationLoaded` / `MatchingCompleted` / `RaidStarted` lines mark raid lifecycle.
3. **Map rendering data**: `https://raw.githubusercontent.com/the-hideout/tarkov-dev/main/src/data/maps.json` provides per map: `transform` (scale/offset ×2), `coordinateRotation` (degrees), `bounds`, `svgPath`/`tilePath` (hosted at `assets.tarkov.dev`), `layers` (floors with height ranges), `labels`, `heightRange`. This is exactly what converts game world coords → map pixel coords.
4. **Marker data**: the free tarkov.dev GraphQL API (`https://api.tarkov.dev/graphql`) provides per map: extracts (with faction + switches), spawn points (PMC/Scav/boss with chances), boss spawn zones, loot containers/points, locked doors + key items, hazards; and all tasks with `objectives { ... on TaskObjectiveItem/Zone maps, zones { position } }` for quest markers.

## Architecture

```
tarkov-overlay/
├── package.json            # Electron + Vite + TypeScript
├── scripts/
│   └── fetch-data.mjs      # Build-time data pipeline (re-run after each game patch)
├── data/                   # Generated by the script, committed/bundled
│   ├── maps.json           # merged: render config + markers per map
│   ├── quests.json         # all quests w/ objective positions per map
│   └── tiles/<map>/...     # downloaded map images (SVG or raster tiles)
├── src/
│   ├── main/               # Electron main process
│   │   ├── index.ts        # app lifecycle, window creation, IPC wiring
│   │   ├── windows.ts      # overlay vs normal window modes
│   │   ├── hotkeys.ts      # globalShortcut registration
│   │   ├── screenshotWatcher.ts  # chokidar on Screenshots folder → parse → IPC
│   │   ├── logWatcher.ts   # find EFT install, tail application log → map/raid events
│   │   └── settings.ts     # persisted settings (electron-store or plain JSON)
│   ├── preload.ts          # contextBridge API (typed IPC surface)
│   └── renderer/           # the map UI (Leaflet)
│       ├── index.html / main.ts
│       ├── map.ts          # Leaflet CRS.Simple map, gameToMap() coord transform, floor layers
│       ├── markers.ts      # extract/spawn/boss/loot/key/quest layer groups + filter state
│       ├── player.ts       # player marker + facing cone + position trail
│       ├── questState.ts   # local quest checklist (localStorage), filters quest markers
│       └── ui.ts           # sidebar: map picker, layer toggles, quest list, opacity slider
```

### Main process responsibilities
- **Two window modes**, one BrowserWindow, reconfigured live:
  - *Normal*: standard resizable window (second-monitor use).
  - *Overlay*: `frame: false`, `transparent: true`, `alwaysOnTop` (level `'screen-saver'`), skipTaskbar; **click-through toggle** via `setIgnoreMouseEvents(true, { forward: true })`.
- **Global hotkeys** (configurable, defaults): toggle overlay visibility (e.g. `F9`), toggle click-through/interactive (`F10`), switch normal↔overlay mode from UI.
- **Screenshot watcher**: chokidar on the Screenshots folder; on new `.png`, parse position/quaternion with the regexes above, send `player-position` IPC, and (optional setting, default on) delete the screenshot afterward to avoid disk clutter.
- **Log watcher**: locate EFT logs (registry → fallback to manual folder pick in settings), tail newest application log, emit `map-loaded` / `raid-ended` IPC. On `map-loaded`, renderer auto-switches map. Purely a convenience; manual map selection always available.

### Renderer
- **Leaflet** with `CRS.Simple`; map image via `imageOverlay` (SVG) or `tileLayer` where tiles exist. `gameToMap(x, z)` implements tarkov.dev's transform + `coordinateRotation`.
- **Floor/level layers**: switch visible layer by UI buttons; when a player position arrives, auto-select floor from `y` vs layer height ranges.
- **Marker layers** (toggleable, faction-aware for extracts): extracts, spawns, bosses, loot containers, locked doors/keys, quest objectives. Popups show name/details (e.g. which key, boss spawn chance, extract requirements).
- **Quest checklist**: sidebar list of quests by trader from bundled `quests.json`; user checks off completed ones (persisted in localStorage). Map shows objectives only for quests not yet completed (with an "available only" filter using `taskRequirements` prerequisites).
- **Player marker**: dot + facing cone from quaternion yaw; keeps a short trail of previous positions; "follow player" toggle recenters on update.
- **Overlay styling**: adjustable background opacity slider so the map can be semi-transparent over the game; UI chrome hides in click-through mode.

### Data pipeline (`scripts/fetch-data.mjs`)
Plain Node script, run manually (`npm run fetch-data`) after wipes/patches:
1. Download tarkov.dev `maps.json` (render config).
2. Query the GraphQL API for maps (extracts, spawns, bosses, hazards, locks, lootContainers, switches) and tasks (objectives with map positions, requirements, trader).
3. Download each map's SVG/tiles from `assets.tarkov.dev` into `data/tiles/`.
4. Emit normalized `data/maps.json` + `data/quests.json` consumed by the renderer.

## Implementation order

1. **Scaffold**: Electron + Vite + TypeScript project boots an empty window (`npm start`).
2. **Data pipeline**: fetch script producing `data/` for all maps; verify one map's JSON + image by inspection.
3. **Map view**: Leaflet renders Customs with correct coord transform (validate: plot a few known landmarks/labels from maps.json and confirm alignment), map picker, floor layers, pan/zoom.
4. **Markers**: all layer groups + toggles + popups; extract faction filter.
5. **Player tracking**: screenshot watcher → position marker + facing cone + floor auto-select. Test with synthetic files copied into the Screenshots folder (no game needed), then live in-game.
6. **Map auto-detect**: log watcher → auto map switch. Test by replaying captured log lines through the parser (unit-style), then live.
7. **Overlay mode**: transparency, always-on-top, click-through, global hotkeys, opacity slider, mode switching.
8. **Quest checklist**: sidebar + persistence + marker filtering.
9. **Polish/package**: settings UI (paths, hotkeys), `electron-builder` portable .exe.

## Verification

- **Data**: after `npm run fetch-data`, spot-check Customs extracts/quest zones against tarkov.dev's own map in a browser.
- **Coord transform**: render maps.json `labels` at their positions — text must land on the right landmarks.
- **Screenshot parsing**: unit test the two regexes against real filename samples (e.g. `2024-01-01[12-34]_-107.42, 2.51, -110.91_0.0, -0.1, 0.0, -1.0_12.29 (0).png`); end-to-end by copying such a file into the watched folder and seeing the marker move.
- **Log parsing**: feed recorded `scene preset path`/`LocationLoaded` lines through the tailer; app switches to the right map.
- **Overlay**: run the game in borderless windowed; verify hotkey toggle, click-through (game receives clicks), opacity, and that BattlEye is untouched (no injection — it's just a separate window).
- **Live session**: one Factory raid — auto map switch on load, screenshot plots position on correct floor.

## Non-goals (v1)

- No live account/quest sync (TarkovTracker, tarkov.dev accounts).
- No runtime API calls — data only refreshes via the script.
- No memory reading / DMA / anything touching the game process.
- No auto-updating of the app itself.
